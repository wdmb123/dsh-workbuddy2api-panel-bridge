下面是 lib/client.js 里真实组件渲染出来的静态快照（浅色 / 深色各一份，用同一套 --dsw-alias-* 变量驱动）。左侧已连接、右侧网关不可达的降级形态。

深色主题 · 已连接

WorkBuddy2API 桥接

把本机自建的 WorkBuddy2API 反代网关（OpenAI 兼容 /v1）接进 DSH，作为一组可选模型。

已连接

1网关连接

填写 WorkBuddy2API 面板里监听的那个地址与 API 密钥。地址带不带 /v1 都可以。

网关地址

默认 http://127.0.0.1:7863/v1，即面板的默认监听端口。

API 密钥

对应面板 config.json 里的 api_key。面板默认开启鉴权，必须填写，否则模型调用会失败；已保存过之后留空即沿用已存的密钥。

2运行状态

宿主侧看到的真实状态。模型路由未注册时，模型选择器里不会出现本分组。

路由注册已注册http://127.0.0.1:7863/v1
可用模型3 个
宿主接口已就绪~/.dsh/.workbuddy2api/config.json

从网关 /v1/models 拉取的模型清单。关掉的模型仍保留在配置里，只是不出现在模型选择器中。

4高级

一般不用改。路由名改动会让模型选择器里已保存的选择失效。

显示名
路由名

小写字母、数字、点、下划线、连字符。

流空闲超时 (ms)

单次流式读取之间允许的最长等待，默认 300000。

启动时自动探测模型关闭后只使用下面已保存的模型清单。

怎么用

  1. 确认 WorkBuddy2API 面板已启动（默认监听 7863）。
  2. 在这里填好地址与密钥，点「测试连接」，再点「保存并生效」。
  3. 打开「设置 → 模型」，在供应商列表里选择 WorkBuddy2API，挑一个模型即可。

配置文件: ~/.dsh/.workbuddy2api/config.json
